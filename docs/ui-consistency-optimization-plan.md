# FileAtlas 界面统一与主题预设优化方案

状态：整体方案（2026-11-06）。目标是解决主题、字体和组件样式彼此冲突造成的界面混乱。当前仅整理方案，未修改程序代码。

## 目标

让 FileAtlas 全部界面使用同一套清楚、稳定的颜色预设、字体层级、控件样式和几何尺度。GPUI Kit 原生 Theme 继续负责解析颜色，UI Bridge 继续提供应用内统一入口；FileAtlas 0.2 的文件浏览结构、多栏工作区和功能行为保持为产品基准。

gpui-kit-material 作为设计参考，借鉴其语义颜色角色、文字层级、形状、交互状态和组件组合方法；不直接引入它的第二套主题运行时。其上游仍处于预发布阶段，并依赖配套 GPUI 底层 revision，因此当前问题优先通过收敛 FileAtlas 自身实现解决。

## 统一后的规则

- **颜色**：移除 Material 主题生成插件及自由调色入口，改用少量固定的原生 GPUI ThemeSet 预设。首批建议为系统默认、经典浅色、经典深色、蓝灰工作台、暖色浅色。预设名、亮暗变体和原生角色映射集中维护，页面不得自带颜色表。
- **字体**：全界面使用现有标题、正文、辅助说明三级层级和字重；插件不自行增加字号、字重或字体缩放规则。
- **组件**：按钮、输入框、菜单、选择器、卡片、导航行、浮窗等相同语义控件，统一从 UI Bridge/GPUI Kit 公共组件构造。确有产品专用行为时，先扩展共享组件并记录理由。
- **几何**：间距、圆角、控件高度和图标尺寸沿用现有共享 token。页面只决定业务排布，不私自重复定义同职责数值。
- **状态**：默认、悬停、焦点、选中、禁用、错误和加载状态使用一致语义；文字前景与实际表面角色成对。
- **动效**：先统一颜色、文字、尺寸和静态层级。Material Expressive 动效只在确有操作反馈价值时考虑，并遵守减少动态效果偏好。

## 实施顺序

### 1. 盘点现有界面偏差

选 FileManager 主窗口、设置页和一个浮动面板，检查标题/正文/辅助文字、按钮、输入、菜单、卡片、树行和表格行。记录绕过共享组件、重复定义样式、前景与表面不匹配、字号和几何 token 未落实的具体位置。使用已有审查能力定位问题，先不改变业务布局。

### 2. 固定主题预设并迁移设置

确认首批预设的名称、亮暗表现与完整 ThemeSet 角色。外观页只允许选择预设和明暗/系统模式，不再提供种子、风格、对比度或单角色改色。设置持久化预设 ID；兼容读取旧 `theme_file`。无法映射的旧自定义主题回退到系统默认并保留原文件，不删除 `%LOCALAPPDATA%/FileAtlas` 中用户数据。

### 3. 收敛主题和公共组件路径

保持 GPUI Kit ThemeRegistry/ThemeConfig 为唯一颜色解析方，UI Bridge 为主题网关。移除生成器 UI、Cordis 服务和 MCP 生成工具后，主题切换仍由统一主题运行时处理。清理只服务于生成器的依赖和设置字段，同时保留旧配置的兼容反序列化。

### 4. 以 FileManager 进行界面试点

先统一主窗口工具栏、导航树行和文件行的字体角色、表面与文字配对、控件状态和共享几何。保持当前单/双/四栏结构、工具行为和 Session 恢复不变。试点稳定后再推广到设置页、浮窗和其他插件界面。

### 5. 逐屏核验并推广

逐套切换主题，检查主窗口、设置、浮窗和代表性控件的默认/选中/悬停/焦点/禁用状态，以及小窗口、长文本和明暗模式。使用同进程 FileAtlas MCP 实际查看运行界面，对照活动参考图记录差异；静态检查和编译不作为视觉验收替代。

## 数据与实现边界

- 不删除用户已有主题 JSON 或其他 FileAtlas 用户文件；仅停止自动应用生成器主题。
- 移除 `fileatlas-plugin-material-theme` 的设置页、Cordis 服务、MCP 工具、生成器专属持久化和 `material-colors` 依赖；先检索所有注册与消费点，确保无孤立引用。
- 新预设数据使用原生 ThemeSet 格式并集中管理；不在插件自绘控件中写 RGB、HSL 或第二份 role palette。
- GPUI Kit 原生 Theme 仍是解析后的唯一颜色来源；UI Bridge 管理主题应用、角色别名和共享产品组件。
- 保留当前主题切换/亮暗模式设置的可读性与兼容性，明确旧设置无法映射时的回退行为。
- 不改变文件数据库、媒体数据、工作区 JSON、多栏状态、Cordis 生命周期和既有业务操作。

## 验收标准

1. 设置页中只出现有限固定预设和模式选择，没有自由颜色生成器或逐角色改色。
2. 每个预设在亮/暗模式下的背景、文字、popover、primary/accent 及状态色有完整且正确的配对。
3. 同语义字体与基础控件在主窗口、设置和浮窗表现一致，插件没有私有 palette 或重复基础控件样式。
4. 旧设置可读取；旧主题文件保持原样；无效或不可映射配置会明确回退，不重置其他设置。
5. FileManager 0.2 布局、多栏导航、选择与持久化行为没有回退。
6. 同进程 MCP 核验覆盖预设切换、主要交互状态与代表屏幕；记录精确参考、结果和未覆盖边界。
7. 主题守卫、架构、功能账本、refresh 等与改动相关的治理检查通过，且生成器插件、工具、依赖和注册项无残留。
