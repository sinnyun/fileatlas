# Eagle 插件文件创建方法

## 核心概念

### Eagle 资源库路径特点

Eagle 资源库路径（如 `X:\xxx.library`）是 **Eagle 内部的虚拟路径**，不存在于实际文件系统中。因此：

- ❌ 不能直接在该路径下创建文件
- ✅ 只能通过 Eagle API 操作文件
- ✅ Eagle 会管理文件到实际存储位置的映射

---

## 文件创建流程

### 推荐方式：临时目录 + addFromPath

```
┌─────────────────────────────────────────────────────────────┐
│  1. 在系统临时目录创建文件                                     │
│     如: C:\Users\xxx\AppData\Local\Temp\collect-canvas\xxx.bood │
│                                                             │
│  2. 使用 eagle.item.addFromPath() 导入到 Eagle                │
│     - Eagle 会自动复制文件到资源库实际存储位置                   │
│     - 返回新创建的 Item ID                                   │
│                                                             │
│  3. 使用 eagle.item.getById(itemId) 获取 item 对象             │
│     - item.filePath 就是 Eagle 分配的实际文件路径               │
│                                                             │
│  4. 删除临时文件                                              │
│                                                             │
│  5. 后续保存直接使用 item.filePath                           │
└─────────────────────────────────────────────────────────────┘
```

### 代码示例

```typescript
import * as fs from 'fs';
import * as path from 'path';

/**
 * 在 Eagle 中创建新文件
 */
async function createNewItemFile(): Promise<{ itemId: string; filePath: string } | null> {
  const tempDir = path.join(process.env.TEMP || '/tmp', 'my-plugin');
  const fileName = '新建文件.bood';  //实际就是json格式文件
  const tempFilePath = path.join(tempDir, fileName);

  // 1. 确保临时目录存在
  if (!fs.existsSync(tempDir)) {
    fs.mkdirSync(tempDir, { recursive: true });
  }

  // 2. 在临时目录创建文件
  const content = JSON.stringify({ /* 文件内容 */ }, null, 2);
  fs.writeFileSync(tempFilePath, content, 'utf-8');

  // 3. 导入到 Eagle（会复制到实际存储位置）
  const itemId = await eagle.item.addFromPath(tempFilePath, {
    name: '新建文件',
    tags: ['my-plugin'],
    folders: [folderId],
    annotation: '插件创建的文件'
  });

  if (!itemId) {
    // 清理临时文件
    fs.unlinkSync(tempFilePath);
    return null;
  }

  // 4. 获取 Eagle 分配的实际路径
  const item = await eagle.item.getById(itemId);
  const actualFilePath = item.filePath;  // 重要：这是实际存储路径

  // 5. 删除临时文件
  fs.unlinkSync(tempFilePath);

  return { itemId, filePath: actualFilePath };
}

/**
 * 保存文件（后续更新）
 */
async function saveToEagleFile(filePath: string, content: string): Promise<boolean> {
  try {
    fs.writeFileSync(filePath, content, 'utf-8');
    return true;
  } catch (error) {
    console.error('保存失败:', error);
    return false;
  }
}
```

## 关键 API

### eagle.item.addFromPath(path, options)

从本地路径添加文件到 Eagle 资源库。

```typescript
const itemId = await eagle.item.addFromPath(filePath, {
  name: '文件名',           // 可选
  website: '网址',          // 可选
  tags: ['标签1', '标签2'], // 可选
  folders: [folderId],      // 可选，文件夹ID数组
  annotation: '注释'         // 可选
});
```

**返回值**: `Promise<string>` - 成功返回 Item ID，失败返回 null

### eagle.item.getById(itemId)

获取指定 ID 的项目信息。

```typescript
const item = await eagle.item.getById(itemId);

if (item) {
  console.log(item.filePath);      // 文件实际路径 ✅
  console.log(item.name);          // 文件名
  console.log(item.fileURL);       // file:/// 格式的路径
  console.log(item.thumbnailPath); // 缩略图路径
}
```

### eagle.folder.create(options)

创建文件夹。

```typescript
const folder = await eagle.folder.create({
  name: '文件夹名称',
  description: '文件夹描述',  // 可选
  parent: parentFolderId      // 可选，父文件夹ID
});
```

## 注意事项

### 1. 路径分隔符

Windows 和 macOS/Linux 路径分隔符不同，使用 `path.join()` 确保跨平台兼容：

```typescript
import * as path from 'path';

// 正确 ✅
const filePath = path.join(folderPath, fileName);

// 错误 ❌（混用分隔符）
const filePath = `${folderPath}/${fileName}`;  // 在 Windows 可能变成 X:\xxx/xxx
```

### 2. 临时目录

确保临时目录存在：

```typescript
if (!fs.existsSync(tempDir)) {
  fs.mkdirSync(tempDir, { recursive: true });
}
```

### 3. 清理临时文件

创建完成后删除临时文件：

```typescript
try {
  fs.unlinkSync(tempFilePath);
} catch (e) {
  console.warn('删除临时文件失败:', e);
}
```

### 4. item.filePath vs item.path

获取文件实际路径应使用 `item.filePath`，不是 `item.path`。

| 属性 | 说明 |
|------|------|
| `item.filePath` | ✅ 文件实际存储路径 |
| `item.fileURL` | file:/// 格式的路径链接 |
| `item.path` | ❌ 不存在，始终为 undefined |

## 常见问题

### Q: 为什么不能直接在资源库路径创建文件？

A: Eagle 资源库路径（如 `X:\xxx.library`）是虚拟的，Eagle 内部管理实际文件存储。直接创建会导致 `ENOENT` 错误。

### Q: addFromPath 后文件被复制到哪了？

A: Eagle 自动将文件复制到其管理的实际存储位置，并通过 `item.filePath` 提供访问。

### Q: 如何处理文件名冲突？

A: Eagle 会自动处理文件名冲突（通过内部 ID 区分）。可以按时间命名，如 `画板0414-1532.bood`、`画板0414-1733.bood`。
