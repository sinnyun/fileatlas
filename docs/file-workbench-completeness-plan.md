# 文件浏览与文件操作：功能完整性和扩展实施清单

日期：2026-10-20  
用途：供后续实现会话作为功能范围、架构边界和验收入口。

## 产品定位与实施原则

本项目是文件浏览器与个人工作台。媒体索引、缩略图、标签、评分和预览是文件浏览工作流中的能力，不代表产品只管理媒体。浏览任意目录不应要求用户先扫描或导入该目录。

实现时先核对当前源代码、crate `PORTS.md`、当前开发基线和 validation 证据。本文状态是实现规划快照，不取代代码检查，也不代表所有 Windows 行为都已验证。代码中的 `fileatlas-*` crate 名称沿用当前 Cargo workspace 命名。

- 复用 Cordis 生命周期、UI Bridge、Database、ReadModel、设置、事件、命令和通用面板；不另建插件管理器或通用存储框架。
- `fileatlas-shell`/Shell 只做启动与宿主组合；文件浏览行为留在现有 FileManager、Navigation 及对应服务中。
- 新功能做成独立编译期 Cordis feature crate 时，必须定义自己的用途、服务/事件/界面贡献和停止清理行为；不能以“插件化”为由复制已有基础设施。
- 任何数据库读写都经共享 `fileatlas-plugin-database` 服务；每项新增持久化选择都在其 PORTS 文档记录格式、路径、版本兼容、迁移和恢复策略。
- UI 变更遵守当前活动参考、主题及 UI refresh 规则，并用同进程 PhoTag MCP 验证。静态编译或单测不代表 Windows 文件操作已验证。

## 状态标记

- **已实现**：当前插件端口/源码明确有此能力；不代表所有平台边界均已验证。
- **部分实现**：有基础实现，但缺少完整语义、恢复能力、体验或运行验证。
- **待实现**：当前检查范围未找到相应完整功能。
- **需核验**：源码/平台行为还需要专门检查或 MCP/Windows 验证。

## 功能清单

### A. 完整任意文件浏览

当前主要归属：`fileatlas-plugin-file-manager`、`fileatlas-plugin-navigation`；目录读取/观察复用 Indexing、Watcher、Database 和 UI Bridge 服务。

| 状态 | 工作项 | 实施与验收要求 |
|---|---|---|
| 已实现 | 任意路径浏览 | 当前生产浏览由文件系统读取驱动，不要求预先导入媒体库。用地址导航打开非收藏目录，确认直接显示该目录内容。 |
| 已实现 | 文件与目录分开呈现 | 浏览器显示文件和目录；目录卡片不伪装成媒体记录。双击/回车进入目录，父级导航返回正确路径。 |
| 已实现 | 文件夹导航 | 地址栏、路径历史、上级目录和刷新由导航契约统一处理，不要在新插件里另造一套地址历史。 |
| 已实现 | 多窗格与程序工作区 | 单栏、双栏、四栏；窗格保留独立路径、选择与滚动，工作区保存启动布局和各栏浏览配置。 |
| 已实现 | 后台分批枚举 | 首批及后续文件批次在后台读取；取消旧请求并拒绝过时代次结果。保持 ReadModel/刷新契约，不在 render 中做 IO。 |
| 已实现 | 空目录、隐藏目录 | 目录读取包含空目录和隐藏目录；递归显示按显式设置工作。 |
| 已实现 | 文件系统变化刷新 | 通过 Watcher/刷新更新目录和会话缓存；后台刷新尽可能保留现有视图、选择和滚动。 |
| 部分实现 | 大目录与长列表 | 明确测量首次可见批次、完整枚举、排序、跳转、选择、内存及刷新时间；覆盖 1k/10k/100k 项或具有代表性的真实目录。找出当前批次与 200 行丰富记录窗口的边界。 |
| 需核验 | 网络盘、不可访问盘 | 验证断网、权限拒绝、盘符移除、慢响应和恢复；错误要局部显示，不能令整个工作台卡死或误报空目录。 |
| 需核验 | 链接、快捷方式及特殊路径 | 记录符号链接目录不递归跟随的既定规则；验证链接文件、快捷方式、UNC、长路径、特殊字符、大小写和盘符根目录。明确不支持项并提供可理解反馈。 |
| 部分实现 | 任意文件预览 | 图片/视频/音频使用现有预览能力；普通文件交 QuickLook。不要把外部交接写成 PhoTag 内置预览。评估需要内置预览的格式，再单独定范围。 |
| 待实现/需核验 | 浏览完整性场景集 | 建立可复现检查：空目录、混合任意扩展名、隐藏项、访问拒绝、外部创建/删除/重命名、目录正在消失、超大目录、断开的网络盘。运行证据放 `.local/validation/`。 |

### B. 复制、移动、删除、重命名

当前主要归属：`fileatlas-plugin-file-operations` 提供文件操作；FileManager 负责选择、目标/确认 UI 和刷新；Database 负责记录协调。

| 状态 | 工作项 | 实施与验收要求 |
|---|---|---|
| 已实现 | 单项复制、移动 | 复用 FileOperations 服务和现有原生目标选择流程；验证成功、取消选择器、目标目录消失及权限错误。 |
| 已实现 | 回收站删除 | 保持明确确认；验证回收站结果、已删除文件的视图移除和取消行为。Windows 原生回收站行为须实际验证。 |
| 已实现 | 重命名 | 确认磁盘路径、数据库/会话缓存、选择和撤销历史同步；名称冲突应保持源文件不变并返回可读错误。 |
| 已实现 | 新建目录 | 验证当前路径合法性、同名冲突、权限错误和创建后视图刷新。 |
| 部分实现 | 冲突决策 | 对目标已存在文件统一定义覆盖、跳过、重命名、取消及是否对后续项目应用同一选择。每个结果可追踪。 |
| 部分实现 | 部分成功/失败 | 每项操作返回成功、跳过、失败、取消等结果；汇总需可查看失败路径与原因，部分成功不能伪装为全成功。 |
| 部分实现 | 取消与中断 | 明确正在进行的操作能否取消、取消后已完成项目如何报告、未完成临时文件如何清理。避免 UI 线程执行阻塞文件操作。 |
| 需核验 | 缓存与跨目录协调 | 对注册目录内移动、移动出注册目录、覆盖、外部同时修改等情况，核对数据库记录、会话缓存、Watcher 和活动视图最终一致。 |
| 需核验 | Windows 行为 | 逐项验证原生文件选择器、回收站、跨卷移动、只读/锁定文件、权限、路径长度及文件名冲突。记录精确场景，不用编译结果替代。 |

### C. 批量操作

当前主要归属：FileManager 的批量操作 UI + File Operations 服务。先补齐现有流程；不要一开始就再建一个复制文件操作实现的插件。

| 状态 | 工作项 | 实施与验收要求 |
|---|---|---|
| 已实现 | 批量复制/移动/删除 | 保留当前选区、当前目录/路径、标签或全库等作用范围和筛选能力；执行时重新验证目标。 |
| 已实现 | 预览匹配数量与目标快照 | 执行前显示匹配数量；删除二次确认绑定目标快照，集合变化时要求再次确认。 |
| 部分实现 | 进度与结果摘要 | 显示总体进度、成功/跳过/失败数量、失败原因和文件路径；支持从结果定位或重试失败项。 |
| 部分实现 | 超大批次 | 评估成千上万项时的内存、UI响应、进度更新频率、取消耗时、日志量与刷新成本；按批处理并限制 UI 消息/刷新频率。 |
| 待实现 | 可复用任务列表 | 只有当批次可能长时间运行、需要同时排队或离开当前面板仍需跟踪时，才增加任务列表。定义暂停、取消、冲突策略、完成通知和重试。 |
| 需核验 | 选择及筛选变化 | 确认预览、二次确认、执行目标和完成后的选区修复始终针对同一组文件，不因切换窗格或外部变化误操作。 |

### D. 撤销与恢复

当前主要归属：`fileatlas-plugin-history` 维护撤销/重做语义；具体操作 crate 产出成功后的可逆记录；Database 提供所需的共享持久化方法。

| 状态 | 工作项 | 实施与验收要求 |
|---|---|---|
| 部分实现 | 现有撤销/重做 | 当前覆盖标签、评分和单项重命名等有限操作；栈上限 100，历史为会话级，不跨重启持久化。 |
| 待实现 | 文件移动撤销 | 仅在操作成功后记录原路径/目标路径及必要身份信息；恢复前检查源/目标状态，不能覆盖外部新文件。冲突要给出安全选择。 |
| 待实现 | 回收站删除恢复 | 评估回收站 API 是否能取得稳定恢复标识；如无法可靠恢复，明确标为不可撤销并保留系统回收站恢复入口。 |
| 待实现/需设计 | 复制撤销 | 明确“撤销复制”只删除本次创建且身份仍匹配的目标文件；不得删除后来替换或修改的目标内容。 |
| 部分实现 | 操作结果语义 | FileOperations 成功/失败结果必须传到 History；失败、跳过和取消不得生成可撤销记录。 |
| 待实现/需设计 | 持久化与过期 | 先按记录数据量和一致性选择格式；小型有限历史可评估版本化 JSON，关系/并发/事务需求复用共享 Database。记录版本迁移、恢复与清理规则。 |
| 待实现 | 历史浏览界面 | 显示操作、时间、文件、可恢复状态和原因；逐条撤销/重做，重启后能识别路径已变化或目标已丢失。 |

### E. 文件暂存篮

文件路径暂存篮已由 `fileatlas-plugin-file-staging` 提供首版；`fileatlas-plugin-clipboard` 仍是剪贴板文字/图片历史，两者用途不同。当前实现范围与验证边界如下。

| 状态 | 工作项 | 实施与验收要求 |
|---|---|---|
| 已实现 | 收集文件路径 | 暂存面板可多选添加任意目录文件；FileManager 卡片菜单可将当前选区加入；规范路径去重。仅暂存文件，不递归添加目录。菜单交互尚未通过实时 UI 点击验收。 |
| 已实现 | 管理暂存项 | 列出来源路径、名称及状态；支持移除单项、清空、重复项去重、刷新失效状态和移除失效项。路径移动后的自动追踪未实现。 |
| 已实现 | 执行复制/移动 | 批量执行并逐项返回结果；同名目标不覆盖，成功项移出暂存篮，失败/冲突项保留重试。MCP 场景已实测。原生目标选择器取消/错误场景未实测。 |
| 已实现 | 工作区切换行为 | 数据独立保存在插件 JSON 服务，不绑定窗格选区或程序工作区；重启持久化已由新 MCP 子进程验证。 |
| 已实现 | 持久化 | 版本化 JSON 保存路径、添加时间和最后可用状态；主文件缺失时可由备份恢复。路径、迁移与恢复规则见插件 PORTS。 |
| 已实现 | 界面与生命周期 | 独立 `fileatlas-plugin-file-staging` Cordis 插件提供浮动面板、Launcher 入口、命令和 MCP 工具，注册随生命周期清理；采用共享主题。窄窗、浅色和所有悬停/焦点状态尚未验收。 |

### F. 文件操作队列（可选独立扩展）

不要将任务队列和暂存篮混为一谈：暂存篮是“稍后选哪些文件处理”，队列是“正在/等待执行哪些作业”。先补齐现有批量操作的进度与结果，再根据实测需求决定是否新增队列插件。

若确定需要跨面板跟踪、长任务排队、暂停/恢复或重启后恢复，可评估独立 `fileatlas-plugin-file-operations-queue` 插件，负责队列状态、任务中心界面和恢复策略；实际复制/移动/删除仍调用 `fileatlas-plugin-file-operations`。不要让新插件自行实现第二套文件传输引擎。其持久化需在设计阶段按任务记录大小、事务及恢复语义选择 JSON 或共享 Database，并在 PORTS 中说明崩溃时处理中任务如何恢复。

## 插件归属决策表

| 能力 | 建议归属 | 是否新建插件 |
|---|---|---|
| 任意路径浏览、排序/视图、目录加载反馈 | FileManager；复用 Navigation、Indexing、Watcher、Database、ReadModel | 否 |
| 单项与批量文件操作、冲突与结果契约 | File Operations；FileManager 集成界面 | 否，先扩展现有插件 |
| 操作撤销/重做及记录 | History；File Operations 发成功结果；必要时扩展共享 Database typed API | 否，先扩展现有 History |
| 文件路径暂存篮 | 新 `fileatlas-plugin-file-staging`；调用现有 File Operations | **是，建议独立插件** |
| 长时作业队列/任务中心 | 可选新 `fileatlas-plugin-file-operations-queue`；编排现有 File Operations | **仅在需求确认后新建** |
| 数据库、通用队列框架、通用文件操作引擎 | 现有共享基础设施 | 否，禁止重复造轮子 |

新插件的 UI/命令/菜单/keymap 等注册项必须由 Cordis 生命周期拥有并在 stop 时清理。插件只实现自身功能和面板内部布局；复用现有 Settings、Database、事件、命令、主题与 UI Bridge 合同。

## 建议实现顺序

1. **代码审计与浏览边界验收**：核对 FileManager 当前真实行为与端口文档；补齐网络盘、权限、长路径、大目录和外部变化验证场景。
2. **文件操作结果契约**：统一单项/批量成功、跳过、失败、取消和冲突结果；完善逐项反馈与重试入口。
3. **批量操作与吞吐优化**：测量大批次进度、取消延迟、内存、Watcher/DB协调及界面刷新频率。
4. **新增文件暂存插件**：已实现首版 `fileatlas-plugin-file-staging`，含版本化 JSON、路径去重/失效状态、原生多文件选择、FileManager 选区入口、复制/移动逐项结果、Launcher 入口、MCP 工具和 Cordis 生命周期清理。同进程 MCP 已验证添加/去重、复制、冲突保护、移动、缺失项清理及重启持久化；原生选择器/目录选择器点击尚未验证。任务取消/恢复仍未实现，具体限制见[PORTS](../crates/fileatlas-plugin-file-staging/PORTS.md)及[运行记录](validation-ui/2026-10-20-file-staging/README.md)。
5. **扩展 History**：基于 FileOperations 结果设计移动/重命名/回收站删除的安全撤销；先约定冲突和持久化策略，再编码。
6. **评估任务队列插件**：以上述实测证明需要跨任务/长任务管理为依据，单独立项，不阻塞前五项。

## 每项功能的完成标准

- 更新所属 crate 的 `PORTS.md`：插件/服务身份、依赖、请求与结果、事件生产/消费、持久化、限制和排错位置与实际签名一致。
- 新增/修改 feature ledger 的条目和证据链接；需要时更新开发基线，而不是让旧历史文档覆盖当前行为。
- 后端行为核对对应现有源实现与 File Operations/Database 调用链；不改变 SQLite schema 或行语义，除非给出兼容迁移与重开验证。
- UI 改动遵循活动参考、`docs/ui-reference-workflow.md`、`docs/ui-theme.md`；使用共享 Theme/组件/浮窗，不加插件私有颜色表。
- 按具体改动运行所需的静态/治理检查，至少评估 `cargo +1.97.1 fmt --all -- --check`、`node scripts/check-ui-theme.cjs`、`node scripts/check-ui-refresh.cjs`、`node scripts/check-architecture.cjs`、`node scripts/check-feature-ledger.cjs`；仅运行与改动相关且必要的 crate 检查/测试。
- 交互和 Windows 文件系统行为通过同进程 PhoTag MCP 在 `.local/validation/profiles/<run-name>` 隔离配置验证；生成数据和截图仅放 `.local/validation/`。未实际运行的路径明确标成未验证。
- 性能优化先记录代表性目录/批次的首批时间、总耗时、峰值内存、取消延迟与错误数，再比较优化结果。

## 新会话启动提示

请先阅读本清单、当前 `AGENTS.md`、`docs/development-baseline-0.2-2026-10-19.md`、`docs/functional-development-plan.md`、相关插件 `PORTS.md` 和 validation 证据；通过 codebase-memory graph 查找实现与调用关系，再读具体源码。先从“代码审计与浏览边界验收”开始，确认当前工作树 crate 名称、实现状态和未验证项。任何需要新插件的功能先完成边界/数据/生命周期设计；文件暂存篮使用独立 feature crate，实际文件操作继续委托现有 File Operations。不要把 PhoTag 描述成仅媒体管理器，也不要把文档状态当作已完成代码或 Windows 验证证据。
