# UI 一致性审查交接（2026-10-23）

## 交接目的

本文供另一模型继续做独立、全面的界面审查。当前阶段以“发现并记录”为主：请检查所有窗口、插件面板和设置页的字体层级、组件类型、尺寸、间距、内边距及按钮状态，把问题按位置和证据列出；本轮审查完成后由用户把问题清单交回实现修复。不要在审查中顺手大范围改样式，以免审查基线变化。

## 当前用户要求

- 全项目所有界面只使用标题、正文、辅助说明三种字体层级；同层字体大小、字重、行高完全统一。
- 间距只使用紧凑、标准、宽松三档；统一样式应由 UI Bridge/GPUI Kit/Settings 主题入口提供，插件只决定组件和布局，不各自定义视觉样式。
- 按钮统一固定高度、最小宽度，宽度由内容决定；框架、卡片、输入控件也应复用共享基础组件。
- 检查应尽量依赖可查询的结构化元素数据，并用全量面板截图核对；不能只凭局部截图推断。
- 字体层级与组件几何的审查色目前仍需保留。用户明确说，只有在用户最终表示“可以了”后才结束颜色审查并恢复正式主题颜色。

## 已经实施、可作为当前审查基线的部分

1. 三层文字组件与临时层级颜色已用于主界面及插件；项目文档已有三层规范记录：`docs/reference-ui/concepts/typography-three-tiers-2026-10-23.md`。正式视觉颜色尚未恢复。
2. UI Bridge 提供结构化几何采集及 MCP 只读查询；全量面板脚本会在截图时同时落盘几何 JSON，避免为每张图手工配置采集。
3. gap/padding/margin 数值已批量归并到三档主题间距（基准 4/8/16 logical px），并由 Settings 的全局布局密度缩放。旧设置缺省为标准密度。
4. 设置外观页有紧凑/标准/宽松布局密度选项。相同设置会缩放三档间距及共享按钮、输入框、导航行等高度 token。
5. FileManager 面包屑按钮的固定最大宽度、筛选行共享按钮上的重复水平 padding 覆盖已移除，并在后续亮/暗全量 atlas 中复核。

## 建议审查记录格式

每条问题请提供：窗口/插件/页面、截图文件或几何 JSON、组件 ID 和源文件/行号（若有）、当前实测值、对照的同层组件/公共 token、具体差异、属于确定问题还是待确认、建议统一到哪个层级/共享组件。请按主题分组（字体、框架、按钮、输入控件、间距/内边距、裁切/小窗口、交互状态），避免只给截图圈选而无法定位。

尤其注意顶部栏与左右侧栏、树行、浮动面板内外部组件、空状态、统计卡片、状态/计数小字、表单标签与说明文字；小字不能因为视觉上较灰就漏出检查范围。横向布局或窗体空间不足时，记录为框架/文案适配问题，不建议临时缩小字体。

## 交接后实现约束

收到审查清单后，先合并去重并定位全部问题，再按共享基础组件和主题 token 批量修复，最后统一做静态检查、构建、同进程 MCP 状态验证及面板截图复核；不要每改一个小点就全量测试。不能在插件内新建私有色板、字体级别、组件尺寸/间距常数来绕过主题框架。审查颜色只有用户明确结束审查后才能清除。
