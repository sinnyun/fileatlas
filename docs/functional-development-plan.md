## 产品方向与新增功能：个人全能工作台（2026-10-17）

FileAtlas 是个人文件浏览器与工作台管理器。文件和目录浏览、独立多栏与程序工作区
管理构成主干；媒体索引、缩略图、标签和检查器是集成在文件浏览流程中的能力。
在现有 Rust/Cordis 插件化框架中逐步增加相互独立、用途可以完全不同的功能插件。
插件可以按具体需求集成脚本、链接或合适的开源库。这里记录的是可扩展方向，
不代表所有设想都已确定或承诺实现。新功能由编译期 feature crate 实现，
通过 Cordis 服务、事件和 UI Bridge 集成；Shell 继续只负责宿主组合。

许可选择不设项目级白名单：这是用户个人使用的工作台，可按功能需要集成适合的
开源组件，包括 GPL-3.0。保留上游版权/许可文件，在插件 PORTS 和验证记录中写明
来源、版本/提交及许可；不要因此静默改动工作区原有的 MIT 声明。若日后分发组合程序，
再按所含组件的许可证履行相应义务。

大多数需要交互界面的功能插件复用现有通用悬浮面板，再在面板内实现自己的
导航、分类、内容布局和该功能范围内的操作。新插件使用宿主已有的数据访问、
持久化、设置、事件、命令及 UI 等基础设施，不重复建设通用基础能力；确有新增
业务数据时，通过现有公共数据能力接入。Cordis 负责插件生命周期及注册项清理。
功能插件丰富与动态加载外部 DLL、插件商店是不同概念；当前仍不引入动态插件加载或商店。

### 插件数据存储选择（2026-10-18）

新功能插件须在设计阶段按具体数据形态选择持久化格式，并在插件 PORTS.md
说明选择理由、目录/文件布局、版本兼容和迁移方式。优先复用宿主已有的
持久化访问与路径约定，不为每个插件另建一套通用存储框架。

- 适合 JSON 文件：数量有限、以整体读取/保存为主、结构清晰且需要用户查看/备份/编辑的
  插件设置、清单、历史或配置数据。采用版本字段、serde 默认值、同目录临时文件写入后
  原子替换；路径位于 `%LOCALAPPDATA%\\FileAtlas\\<feature>\\`，媒体等大资源独立存放，
  JSON 使用相对路径或稳定标识引用资源。
- 适合 SQLite：数据量较大或持续增长、需要过滤/排序/分页/全文检索、并发读写、事务约束、
  关系完整性或增量更新的数据。复用 `fileatlas-plugin-database` 的 DatabaseService，
  schema 与 typed API 由该 crate 持有；不得由功能 crate 自行打开 SQLite。
- 混合数据：元数据使用所选结构化存储，二进制图片、图标、附件等始终作为独立文件/缓存；
  结构化记录保存相对路径、内容哈希和必要的尺寸/时间信息。可重建缓存与用户原创资源须区分，
  清理时不得误删用户数据。

按此规则，剪贴板工作台与程序启动台的用户数据目标格式为各自独立 JSON 文件，图片/图标
继续独立存储；照片库、标签等高查询量关系数据仍使用共享 SQLite。剪贴板与启动台已完成
JSON 迁移：首次缺少 JSON 时从旧表导入并写入版本化文件；此后 JSON 为唯一运行时来源，
SQLite 原表保留作恢复数据。详细运行证据见
[`JSON 插件存储迁移验证`](validation-ui/2026-10-18-json-plugin-storage/README.md)。

### 首个工作台功能：程序启动台

新增独立 Cordis 功能插件，在左侧侧面板注册启动台入口；点击入口打开现有
通用悬浮面板。面板采用左侧分类栏、右侧程序列表的布局，作为个人常用程序的
快捷启动和管理工作台。

- 扫描系统中可发现的已安装程序并自动添加；也允许用户手动添加程序或快捷方式。
- 支持创建/管理分类、将程序移入其他分类、修改显示名称及启动程序。
- 支持隐藏工具类程序；隐藏项不出现在默认启动列表中，并可在管理视图恢复显示。
- 提供卸载操作。对已安装程序调用其系统注册的卸载入口，并在执行前明确确认；
  不自行删除程序文件或绕过系统卸载器。快捷方式或无法识别卸载入口的项目不提供卸载。
- 自动发现与手动整理须通过现有数据/持久化基础设施保留用户修改过的名称、分类和隐藏状态；重复发现时合并，
  不覆盖用户整理结果。失效路径应可识别并允许移除或重新定位。
