# WorkCrate Boards ports

Cordis plugin `fileatlas.workcrate-boards` publishes `fileatlas/workcrate-boards` and depends on Projects. `VectorCraftConfig { executable, cli_executable, port }` remains in `vectorcraft.json`; both executable fields are optional strings and `port` defaults to 17979. A blank CLI path is resolved as `vectorcraft-cli.exe` beside the configured GUI executable. The legacy loopback transport is used only by `connect()` and `open_editor()`; only an explicit editor action starts the GUI.

`board_catalog`, `load_board`, `board`, `boards_for_project` and `render_preview` read FileAtlas-owned `projects/<uuid>/boards-cache.json` and `native-previews/` only. They never start or contact VectorCraft. A missing catalogue is empty; a missing cached preview returns `PreviewUnavailable`. Cache entries are bound to the persisted native-document association UUID, so `attach_document` clears old cache and any binding rotation makes old board IDs unavailable.

`create_project_document(project, directory)` creates the first A3 landscape document through the official `vectorcraft-cli.exe mcp --headless` JSON-RPC stdio server, writes the `.vectorcraft` file into the selected folder without overwriting, adds the native material header, and stores catalogue/preview cache inside FileAtlas. `refresh_project(project)` is the explicit disk-to-cache synchronization action; it refuses to read a same-project GUI document while it is dirty. Both operations use bounded child lifetime, hidden Windows process creation, isolated CLI preferences under the FileAtlas project root, and one explicit native-folder read/write root. Preview PNG bytes are returned inline by the official renderer and written into FileAtlas by the manager.

`create_page`, `update_info`, `place_reference`, `place_file`, and `export_native` use the official headless CLI and refresh the durable snapshot after successful writes. The manager does not save a live GUI document; save canvas edits in VectorCraft, then use `refresh_project` to synchronize the local catalogue and previews. A background write is refused while the same document is open in the GUI to prevent stale in-memory state from overwriting the saved file. Placement requires the native document and source file to share a safe read root; cross-volume sources are refused. Export reads from the native folder and writes to the chosen output folder. `open_editor` alone connects to or starts the GUI, navigates to the live artboard, and focuses the editor. The legacy TCP JSON-line client remains bounded and validates response IDs; headless MCP uses newline JSON-RPC, bounds replies to 32 MiB, times out at 65 seconds, poisons the process after uncertain/remote outcomes, and never retries a mutation.

Page identity remains project UUID + persisted association UUID + native numeric artboard ID. Header content is real native text tagged with versioned `fileatlas.workcrate` notes; edits are undo grouped. Raster/PDF exports are official CLI exports and are atomically placed at the requested output path. Inspect failures through returned BoardsError values and the WorkCrate UI/MCP operation message. No upstream source or renderer dependency is embedded.
