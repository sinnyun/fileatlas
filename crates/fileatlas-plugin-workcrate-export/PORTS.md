# WorkCrate Export ports

Cordis plugin `fileatlas.workcrate-export` publishes `fileatlas/workcrate-export`, requires Boards service. Public constructor `new(Arc<WorkCrateBoardsService>)`, `progress() -> Option<String>`, export_pages_pdf, export_pages_images, export_page_image, export_page_pdf retain shell/service integration.

All file generation uses the official VectorCraft CLI headless MCP export through Boards. PDF selection uses current native indices; all selected pages must belong to one associated native document. Images support PNG/JPG at 300dpi. ExportedPage retains existing path,dpi,width_px,height_px fields. Native output is generated into a fresh temporary file, file completion is checked, then atomically handed to requested path. Count results indicate completed output; native warnings are retained in progress on success. Failure progress persists for PDF; image failures return ExportError.

PDF exports start with the official built-in `VectorCraft Default` preset, disable `preserveEditing`, and set color/gray image compression to JPEG `high`, bicubic downsampling to 300 PPI above 300 PPI, with text compression enabled. Other settings retain official defaults. Opaque images use JPEG; transparent images follow the official exporter's supported handling. Native text/vectors remain native PDF content; this is not whole-page rasterization. Both single-page and multi-page exports share the Boards path. See `scripts/validate-workcrate-pdf-jpeg.cjs` for before/after image compression verification and `scripts/validate-workcrate-pdf-defaults.cjs` for text/page/attachment regression checks.

No PdfCraft, image encoder, own renderer or raster PDF generation. No process ownership/cleanup beyond underlying client lifetime. Native errors and progress provide diagnostics; no event producers/consumers. Integration runtime remains separately verified with the ignored official_native_round_trip test.
