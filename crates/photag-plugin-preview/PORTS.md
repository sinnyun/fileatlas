# Preview plugin ports

Status: image preview service and native GPUI preview surfaces are implemented. The Gallery opens selected media with its database identity. The AI suggestions surface polls local inference, reads live AI settings, and supports assigning/removing suggested tags. Source wheel multiplier, fit/preset zoom, cursor-anchored zoom, drag pan, and a toggled file/image/EXIF information overlay are available; source visual parity remains incomplete.

## Lifecycle and dependencies

- Cordis plugin name: `photag.preview`; service: `photag/preview` (`PreviewService`).
- The plugin owns its `preview/image` and `preview/ai-suggestions` panel contributions and both view factories through `photag-ui-bridge`; Cordis disposal removes them.
- Requires `SessionService` at startup to restore/save the last preview source path. Configure the transform cache with `PreviewConfig.cache_dir`; default is `%LOCALAPPDATA%/PhoTag/preview` (system temp directory when unavailable).
- Also requires `AiService`, `SettingsService`, `TaggingService`, and `HistoryService`. Shell starts Preview after all four providers; Gallery mode enables Tagging and History so the preview can apply and undo suggestions.

## Input / output

- `open(path)` selects a source and resets its view; `open_media(path, media_id)` additionally carries the indexed row identity in `PreviewSnapshot::media_id` for consumers such as AI suggestions. `close()` clears current selection. The Info button toggles a scrollable overlay adapted from `vendor/photag-source/src/ui/preview.rs` and `src/ui/info.rs`.
- The `preview/ai-suggestions` surface reads a fresh AI settings snapshot on request and automatic image changes. Auto-analysis runs only when enabled and the model is already present; manual Analyze downloads a missing model before inference. It shows worker results/errors and routes Apply/Remove actions through `TaggingService`, which creates unknown labels under `AI Suggested` and synchronizes metadata using its standard path. A successful Apply pushes `UndoEntry::AssignedTags` with the exact direct label IDs after the DB mutation succeeds, matching the source AI action; failed DB mutations create no history entry. Video and audio extensions are excluded.
- A result is scoped to `(source path, media ID)`. Changing preview discards the receiver and visibly reports that the result is abandoned; the current AI engine has no cancellation token, so the detached inference worker can finish in the background. Automatic analysis attempts each image once per panel lifetime, including errors, matching the source's no-repeat auto-trigger; manual Analyze can retry.
- The panel reads filesystem name/path/type/extension/size/read-only/created/modified facts, image dimensions/aspect/megapixels, and the source's curated plus complete EXIF fields. For video extensions it invokes the source-compatible `ffprobe` lookup and shows dimensions, duration, frame rate, video codec, bitrate, and audio codec. Probe results are cached per path and file modification time. Byte/date/aspect formatting follows the source conventions. EXIF dates remain in the decoded EXIF values; filesystem timestamps use local time.
- `rotate_clockwise`, `rotate_counter_clockwise`, `flip_horizontal`, and `flip_vertical` adjust non-destructive preview transforms. `set_fit` restores fit mode; `set_zoom_percent` accepts the source presets 25, 50, 100, 125, 150, and 200. `toggle_info` controls the information panel.
- GPUI wheel input reuses PhoTag's `old_zoom * (1 + scroll * 0.0025)` calculation and clamps the continuous scale to 5%–1600%. The default is center-anchored; `toggle_zoom_at_cursor` applies the source pan adjustment that keeps the cursor's image point stationary. Left-button drag pans by pointer delta. Fit uses the image/viewport ratio capped at 100%, as in the source preview.
- `snapshot()` returns current source path, transforms, fit/zoom settings, info visibility, and a revision counter.
- The Preview toolbar is centered near the bottom of the stage. Its drag handle applies transient pointer deltas to the stored center-bottom offsets and writes the final offsets to `SettingsService` on mouse release. A locked toolbar does not start a drag; effective offsets are clamped to the current viewport after resize and persist when the user next drags. Persistence failures are shown on the surface. Settings also provides lock and reset controls.
- `PreviewPlugin` reopens `session.json`'s `preview_path` when the image still exists and clears the saved path when that file is missing. Opening and closing updates that field. Transform, zoom, pan, zoom-anchor mode, and information visibility are saved in backward-compatible optional session fields and restored for the matching path. Keyboard `F`/`0` fits, `+`/`-` steps through source zoom presets, arrows navigate, Escape closes, `I` toggles info, and `R` rotates clockwise.
- Preview requires `FileOperationsService` and routes F2 or the Rename control through its source-compatible rename path. The service updates the matching preview path in place, preserving transform state, media identity, and filmstrip navigation. Delete/Backspace and the Delete control show a native confirmation before calling `delete_to_recycle_bin`; successful row removal advances to the next supplied filmstrip item, or the previous item when deleting the last one, and closes when no neighbor remains. It retains each neighbor's media ID so the AI surface remains scoped correctly. `MediaIndexChanged` triggers the existing Gallery refresh. Recycle Bin errors are shown even when the source row was removed. If event delivery fails after a mutation, the action reads the row again before repairing the preview.
- `set_filmstrip(paths)` supplies ordered image paths; `set_filmstrip_media((path, media_id))` also retains row identity for navigation and preview actions. Gallery supplies the filtered query's ordered image records. The panel displays up to seven nearby thumbnails and supports previous/next navigation with the arrow keys while focused. Nearby 96 px filmstrip images and 1600 px preview frames are generated through a two-worker background queue under the preview cache.
- In fit mode, a newly decoded 1600 px frame is shown for up to 500 ms while GPUI starts loading the original image; the panel polls for decode completion and this quality transition. Cache completion refreshes the view. Decode failures leave the original-image path as the fallback, and the worker queue shuts down when the preview service is dropped.
- `display_path()` returns the original path when untransformed and otherwise returns a cached PNG copy with rotation and flips applied. It never writes the source media.

## Consumers and debugging

- A caller should invoke `PreviewService::open_media` when an indexed item is selected for preview, so per-image AI actions retain the media ID; `open` remains available to path-only callers. The Gallery opens previews through this service.
- Decode or cache write failures are returned by `display_path` as `PreviewError` and shown in the GPUI image area. Image orientation metadata is not reapplied in this transform path. The source panel's assigned tags, engagement/open count, indexed `date_taken`, and source-themed modal framing remain unavailable. Smooth zoom animation, toolbar exclusion during wheel zoom, auto-hide chrome, and loading the filmstrip beyond the caller-supplied paths remain incomplete. Viewport dimensions are estimated from the window bounds and should be verified in the integrated Windows layout. `ffprobe` metadata remains unverified on Windows deployment layouts.
- `photag-plugin-thumbnails::thumbs` remains the source-compatible thumbnail generator; it is intentionally not used for full-size preview decode.

## Shared visual tokens

The preview information panel and status messages use photag-ui-bridge::theme for source modal/base surfaces, accent headings, secondary text, and danger text. Windows visual parity is unverified.
